# PhotoHDRFix 收尾结论（v2.3.0）

## 一、项目定位
纯 App 层 Xposed 模块，解决玄戒 O1 平台（dijum）MIUI/澎湃相册多场景瞬间偏黄问题。
包名 `com.wa2000.photohdr`，作用域 `com.google.android.apps.photos, com.miui.gallery`。
全程不碰 system_server / sepolicy / vendor / 系统引导，零系统风险。

## 二、根因链（最终定性）
1. 用户相机拍的杜比视界视频，底层即 HLG（Profile 8.4，transfer=arib-std-b67，BT.2020）。
2. 玄戒平台色彩管理缺陷：HDR 图层合成时 colorTransform 为单位矩阵，HLG OOTF 未处理，
   BT.2020 数值被直接当 P3 显示 → 中性色偏黄，且固化在合成阶段，截图同样发黄。
3. 触发条件收窄：只在屏上出现 HDR 图层那一刻偏黄（信息流缩略图 / 截屏动画 / 录屏），
   普通全屏查看不偏（无 HDR 图层时 dataspace 为 V0_SRGB、colorTransform 单位矩阵）。

## 三、修复策略（最终落地，方案 A）
`MediaCodec.configure` 钩子按 Surface 类型分流：
- **全屏**（Surface 子类，如 jfd）：mime 重写 hevc + 缺失才注入 BT.2020(6)/HLG(7)，保留真 HDR，不碰 csd-0。
- **缩略图/预览**（原生 android.view.Surface，父类 Object）：mime 重写 hevc + 无条件压 SDR(BT.709)，
  并 `patchCsd0ToSdr` 覆写 SPS VUI 三字节（64/65/66 → 0x40），双保险兜住玄戒解码器无视 configure 的坑。
- 另：`createByCodecName`/`createDecoderByType` 重定向 dolby 解码器 → hevc 解码器。

`patchCsd0ToSdr` 双护栏（已保留）：
- 护栏1：duplicate 读原 ByteBuffer，不原地污染。
- 护栏2：`len==93 && bytes[64]==0x42 && bytes[65]==0x44 && bytes[66]==0x82` 精确命中才覆写。

## 四、功能闭环状态（用户实测裁决，最高优先级）
- ✅ Google 相册：全屏 HDR 保真、信息流缩略图不黄、截屏图片回看不黄。
- ✅ 自带相册：信息流缩略图不黄。
- ⚠️ 截屏动画偏色：**已知系统边界，用户选择接受保留，不再修**。
  本质：动画期间 `numHdrLayers(1)` 图层即截图缩略图缩小动画（255×255→43×215），
  绘制者为 SystemUI/system_server 截图控制器；修复必 hook system_server → 越红线 → 红线内不可修。

## 五、红线条目（持续生效）
不改 zygisk_lsposed/sepolicy.rule、不注入 system_server、不在 db 启用 dfobserver、
不重启 lspd、不动系统引导模块、不动系统文件、不碰 /vendor、不碰截屏/录屏系统进程。

## 六、本次日志精简（逻辑零改动）
删除：`sConfigureCount`/`sDvFixCount` 字段与自增、高频 `MediaCodec.configure` 明细块、
`[FULLSCREEN->HDR]`/`[THUMBNAIL->SDR]` 判定日志、`[CSD0-PATCH]` 系列、
辅助方法 `describeArg`/`logStack`/`safeInt`/`dumpCsd0`/`bytesToHex`。
`patchCsd0ToSdr` 签名 `(MediaFormat,int)` → `(MediaFormat)`，catch 改 `Throwable ignored`。
保留：启动 `v2.3.0 Initializing`、`Successfully hooked ...`、`[CODEC REDIRECT]`、
`[TYPE REDIRECT]`、`Settings loaded/updated` 等低频关键日志。

## 七、软重启误判教训
软重启 lspd 5075→28011 后取证时系统 load 22.48 正处高负载拉起期，
多次 force-stop gallery 零注入被误判「模块整体未加载」，被用户实测推翻。
归因：注入延迟/日志未落盘 + 取证时机不当。后续不急于下「模块未加载」重结论。

## 八、潜在缺陷（归档，不处理）
`patchCsd0ToSdr` 护栏只认 len==93；历史存在 len==92 的 HDR 流，理论上漏修。
用户已收尾、实测未见问题，仅作记录。
